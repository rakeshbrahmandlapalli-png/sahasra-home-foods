───────────────────────────────────────────────────────────────────────
 STEP 3 — build the tables
───────────────────────────────────────────────────────────────────────
 In the left sidebar click  SQL Editor  →  "New query".
 Open the file  setup/schema.sql  from this folder, select ALL of it,
 copy, paste into the box, and press  Run.

 You should see "Success. No rows returned". That is correct.


───────────────────────────────────────────────────────────────────────
 STEP 4 — put the menu in
───────────────────────────────────────────────────────────────────────
 Same place: SQL Editor → New query.
 Open  setup/seed.sql , copy all of it, paste, press  Run.

 Then click  Table Editor  in the sidebar. Open the "items" table.
 You should see 36 rows. If you do, the menu is in the database.


───────────────────────────────────────────────────────────────────────
 STEP 5 — create the login that can edit the menu
───────────────────────────────────────────────────────────────────────
 5a. Sidebar → Authentication → Users → "Add user" → "Create new user".

       Email:    whoever will edit the prices
       Password: pick a strong one and save it in a password manager
       Tick:     "Auto Confirm User"

     Click "Create user".

 5b. NOW GIVE THAT PERSON PERMISSION TO EDIT.
     Creating the login is not enough on its own — on purpose.

     Go to SQL Editor → New query, put in the line below with their
     email in place of the example, and press Run:

       insert into admins (user_id, email)
       select id, email from auth.users where email = 'her@email.com'
       on conflict (user_id) do nothing;

     It should say "Success. 1 row". If it says 0 rows, the email does
     not match the one you typed in 5a — check the spelling.

     Repeat 5a and 5b for each extra person. Only add people you trust:
     anyone on this list can change every price on the site.

 5c. TURN OFF PUBLIC SIGN-UPS.
     Sidebar → Authentication → Sign In / Providers → Email.
     Switch OFF "Allow new users to sign up". Save.

     Without this, strangers can create themselves an account. They
     still could not edit anything (step 5b is what grants that), but
     there is no reason to let them in at all.

 *** NEVER send any of those passwords to me. ***

───────────────────────────────────────────────────────────────────────
 ONE THING TO KNOW ABOUT THE FREE PLAN
───────────────────────────────────────────────────────────────────────
 Supabase pauses free projects that get no traffic for 7 days. A live
 site with visitors will not pause. If it ever does, you un-pause it
 from the Supabase dashboard in one click — and in the meantime the
 fallback copy keeps the customer menu working.
